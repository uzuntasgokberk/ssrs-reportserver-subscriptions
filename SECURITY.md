# Private vulnerability reports

Do not disclose vulnerabilities, credentials, production workbooks or raw execution logs in public issues
or pull requests.

On the published GitHub repository, use **Security > Report a vulnerability** if private reporting is enabled.
If that option is unavailable, wait until a private reporting channel is established with the maintainer;
do not publish exploit details or sensitive attachments as a workaround.

Use synthetic input and the minimum information needed to reproduce the problem. Include the script
release, Windows PowerShell version and affected report-server product/version.

This project uses the current Windows identity. Never send account passwords or credential exports.
